# Security Policy

## Supported version

Security fixes are evaluated for the current published release line. Reproduce against the newest published tag before reporting when it is safe to do so. A report is not permission to install, replace, publish, or release anything.

## Report a vulnerability privately

Report suspected vulnerabilities only through GitHub Private Vulnerability Reporting:

https://github.com/banqiusheng/visual-first-ppt/security/advisories/new

Do not open a public issue, discussion, or pull request for a vulnerability. Include the affected version, impact, minimal reproduction steps, and a redacted diagnostic description. Do not include real credentials or customer files; use synthetic examples.

Do not include tokens, passwords, account identifiers, personal absolute paths, or customer decks.

The project maintainers will triage the private report and coordinate any disclosure or release decision. Submission does not promise a particular remediation date and does not grant publication authority.
